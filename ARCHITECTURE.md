# Architecture

Kontor is a **single-page, framework-free, client-only** web app. The whole UI
is one HTML file with inline CSS, driven by one vanilla-JS file, plus a small
storage module and self-registering reference-content modules. There is no
build step for the app itself.

## Files & load order

The browser loads classic `<script>` tags in this order (they share one global
lexical scope — relevant for the tests below):

1. `sources/finhub-*.js` — register reference content onto `window.FINHUB`
2. `storage.js` — defines `FDStore`
3. `finance_dashboard.js` — the app (reads `FDStore` and `window.FINHUB`)

`finance_dashboard.html` holds the markup and **all** CSS inline. `init()` runs
on `DOMContentLoaded`.

## The three tabs

Tab buttons map to containers (note the historical id naming):

| Tab label | Container id  | Layout root        | What it is                         |
|-----------|---------------|--------------------|------------------------------------|
| Track     | `#tabTrack`   | `#mainTrack.main`  | income + grouped expenses          |
| Plan      | `#tabInvest`  | `#mainInvest.vgroup`| securities/investment tracker     |
| Sandbox   | `#tabPlan`    | `#mainPlan.hgroup` | retirement projection              |

## Calculation engine (`finance_dashboard.js`)

Pure, DOM-free functions (these are what the test suite targets):

- **Tax** — `applyTax(eqGain, bdGain, useSpb)` and `effRate(eqW)` implement
  Abgeltungsteuer (`ABG = 0.26375`), the 30% equity Teilfreistellung
  (`TF_EQ`), and the €1000 Sparer-Pauschbetrag (`SPB`).
- **Projection** — `computeModel(p)` runs a month-by-month accumulation
  (contributions + step-up + equity glide-path) then a decumulation
  (inflation-adjusted withdrawals, tax-aware), and binary-searches the
  sustainable withdrawal. Returns `{ p, accM, decM, N, eq, mix, paid }`.
- **Expenses** — `monthlyRate(e)` (yearly ÷ 12), `activeCount(e)`,
  `annualActual(e)` (rate × active months), `annualFull(e)` (12-month
  equivalent).
- **Formatting** — `eur(x)` (compact €, k/M suffixes, de-DE grouping),
  `parseNum(str)` (de-DE-aware: grouping dots, decimal comma).
- **Sanitisation** — `sanitizeSecurities(s)` normalises the securities object
  on load/import (keys must be `YYYY-MM`).

`P()` reads the slider/input DOM into a params object for `computeModel`; the
engine itself never touches the DOM.

## Storage layer (`storage.js`)

`FDStore` is the single seam for persistence — the rest of the app never calls
a storage primitive directly:

- `readSync()` — synchronous read from **localStorage** (instant boot).
- `write(obj)` — writes localStorage immediately and **IndexedDB** (debounced).
- `readDurable()` — async read from IndexedDB.
- `requestPersistence()` — asks the browser to keep storage.

Why both: localStorage gives a synchronous boot but iOS Safari (ITP) can evict
it after ~7 days; IndexedDB is the durable mirror. On boot, `hydrateDurable()`
marks storage persistent and, if localStorage was evicted but IndexedDB still
holds data, restores it. Import/Export JSON is the manual backup path. A future
remote-sync backend would implement the same `read*/write` contract.

## FinHub reference (`sources/finhub-*.js`)

Each module pushes a tab onto `window.FINHUB.tabs`. `renderFinHub()` lazily
builds the info modal from them on first open, reusing the dashboard's own CSS
classes so it tracks theme/density automatically.

## PWA (`manifest.webmanifest`, `sw.js`)

- **Manifest** — installable metadata, brand colours, maskable icons; relative
  `start_url`/`scope` so it works under the `/kontor/` project subpath.
- **Service worker** — precaches the app shell (HTML/JS/CSS/fonts/icons) for
  offline use; cache-first with network fallback. Fully same-origin (no
  cross-origin handling needed since fonts are self-hosted). **The `CACHE`
  constant must be bumped on every shipped change** — cache-first clients
  otherwise keep the old shell. `skipWaiting()` + `clients.claim()` make new
  versions take over promptly.

## Fonts (`fonts.css`, `fonts/`)

Fraunces, Spline Sans, Spline Sans Mono (SIL OFL), self-hosted as woff2
(latin + latin-ext). Mirrors what Google Fonts served, so rendering is
unchanged — but with **zero third-party requests**. Regenerated by
`tools/fetch_fonts.py`.

## Rendering

Charts are hand-rolled on `<canvas>` (no chart library). Theme is driven by CSS
custom properties; `applyAccents()` writes accent-derived variables at runtime.
Light/dark, density, and a colour-profile picker are all CSS-variable swaps.

## Mobile layout

Breakpoints layer on top of the desktop layout:

- **≤600px** — bottom tab bar (tabs become a fixed, thumb-reachable bar); the
  header action cluster collapses into a `⋯` menu; the expense table becomes
  stacked **cards** with a 6×2 month-toggle grid.
- **≤980px** — the desktop drag/resize/reorder dashboard (gutters, in-group
  dividers, tile-swap grips) is hidden; tiles stack at natural height with a
  uniform gap, and JS-applied inline sizes (`flex`/`width`/`height`/`--hgh`)
  are reset via `!important` so nothing is clipped or misaligned.

Desktop keeps the draggable, resizable tile dashboard (`wireSplitter`,
`wireHGDiv`, `wireVGDiv`, tile-swap), which writes inline sizes onto tiles and
persists them to localStorage.

## Tests (`test/`)

Node's built-in runner (`node --test`), with `jsdom` + `fake-indexeddb` as the
only dev dependencies.

- `test/_loadApp.mjs` — concatenates the browser scripts and runs them as **one
  script** in a `vm` context with a jsdom DOM, so top-level `const`/`function`
  bindings resolve across files exactly like classic `<script>` tags do. It
  surfaces the pure functions for testing.
- `test/storage.test.mjs` — the FDStore round-trip + the localStorage-eviction
  recovery path.
- `test/calc-*.test.mjs` — tax, projection, expenses/formatting, securities.

Because the calc functions are pure and DOM-free, they're tested by calling
them with constructed inputs and asserting known invariants — no rendering
required.

## Conventions

- After changing shipped HTML/CSS/JS: **bump `sw.js`'s `CACHE`**.
- `.gitignore` keeps user-data `*.json` out but tracks `package*.json`;
  `node_modules/` is ignored.
- Pages deploys repo root from `master`; `.nojekyll` serves files verbatim.
